# 普通攻击、碰撞与胜负规则

规则定义位于 `src/dollfight/combat_rules.py`，几何结算位于 `combat.py`，比赛模式由 `match.py` 提供。Unity 当前默认采用下文的单局 KO 模式；Motion Lab 仍保留旧三回合排练供浏览器算法对照。规则适用于原场地和 Saint Maurice 场景。画面布局与操作见[对战画面与操作](combat-presentation.md)。

## 伤害与出招

| 普通动作 | 伤害范围 | 躯干基准 | 识别后有效时段 / 后摇 | 格挡消耗 |
| --- | ---: | ---: | ---: | ---: |
| 直拳 | 6–10 | 8 | 0.32 / 0.18 s | 15 |
| 勾拳、普通反手拳 | 8–12 | 10 | 0.32 / 0.24 s | 17 |
| 上勾拳 | 9–13 | 11 | 0.32 / 0.28 s | 18 |
| 旋转反手拳 | 12–17 | 14 | 0.85 / 0.45 s | 22 |
| 膝击 | 10–15 | 12 | 0.35 / 0.30 s | 19 |
| 前踢 | 11–16 | 13 | 0.40 / 0.35 s | 20 |
| 侧踹 | 13–19 | 16 | 0.40 / 0.45 s | 23 |
| 回旋踢 | 14–20 | 17 | 0.45 / 0.50 s | 24 |
| 旋踢 | 17–24 | 20 | 0.85 / 0.60 s | 28 |

头部在基准上加 2，腿部减 2，命中前摇或后摇再加 2，最终限制在该动作伤害范围内。左右手脚规则相同，无随机暴击，也不按识别置信度放大伤害。表中是识别事件的默认时段；排练指令使用各自动捕片段已有的前摇、有效和回收标注，前摇不造成伤害。

每个攻击 ID 每回合只接受一次，一次出招最多结算一次接触。后摇和受击硬直期间不能再出招；受击会永久取消该次尚未结算的攻击。同一时刻双方均已成立的命中允许互击和双 KO；不同时间的接触按先后结算。

旧排练中部分“看见打到但没掉血”的主要原因是动画与 recovery 锁定不同步：新攻击已因后摇或受击硬直被规则拒绝，编排动画仍继续播放击打。默认 showcase 使用完整的单次拳击摘录与单次踢击轮流编排，保留前摇、有效期和回收间隔，避免新攻击落入前一次锁定期。此次导出没有 recovery 拒绝或取消的攻击；通用伤害规则和判定体大小保持原值。HP 仍由有效期内的实际几何接触、防守和伤害规则决定，普通格挡保持不扣 HP。

## 判定体与防守

拳为手部半径 9 cm 的球，膝为半径 12 cm 的球，踢为脚踝至脚尖半径 12 cm 的胶囊。脚尖失跟踪时退化为脚踝球。受击体为头部半径 14 cm、骨盆至胸部半径 19 cm、左右大腿和小腿半径 9 cm 的胶囊。衣服、头发、武器装饰、肩甲和个人视角骨架不扩大命中范围。

两人姿态在帧间同时插值，相对位移每 2.5 cm 以内采样，检测攻击体与受击体之间的距离。无效节点、跟踪恢复或过长采样间隔不连接成攻击轨迹；过期攻击窗口不会因低帧率延长。

格挡必须满足朝向、实际前臂接触、有效防守姿态和可防守状态。普通格挡不扣 HP，按表消耗防守槽；不足则破防并造成伤害及 0.8 秒硬直。原有精准拨挡保留，成功后攻击方硬直 0.4 秒。防守槽上限 100，开放姿态每秒恢复 9，架防时每秒恢复 3；已结束回合不恢复。

## Unity 展示短局与历史回合模式

Unity 默认使用动作更快、攻防更密集的 showcase 单局，**1.2 倍源速率、66 源秒常规时限，对应 55 秒倒计时**。双方从 100 HP 开始，不同动作段之间 HP 连续。默认展示速率与常规时限由导出的 `presentationRate`、`regulationDuration` 决定，HUD 与播放时钟使用同一换算。任一方 HP 归零立即 KO 结束；双方同时归零为双 KO。常规时限到后仍无人 KO，则进入加时并继续结算，直到出现 KO。旧时间轴未提供展示速率时保留原兼容行为。

当前 showcase 在 54.7 源秒、显示时间 45.5833 秒结算真实 KO，最终 HP 为 51 / 0、P1 获胜。共 10 次命中、10 次格挡、0 次挥空，P1 / P2 分别命中 7 / 3 次；直拳、前踢、侧踹、回旋踢和腾空旋踢五类招式均产生真实伤害。教堂原生自然连播含稳定终局的完整记录共 48.063 秒，实际记录和原生接触复核见[对战画面验证记录](combat-presentation.md)。

调试可在设置 → 排练工具中使用时间轴、下一次交锋和跳到终局。跳到终局会定位到真实终结一击之前，再由原动作和 Python 结算产生 KO，不会伪造血量或结算事件。

旧三回合规则仍用于 Motion Lab 浏览器模式和已保存的历史排练：每回合 30 秒、100 HP，KO 后该回合停止伤害，超时按剩余 HP 判胜，每回合重置 HP、防守槽、攻击 ID、硬直和出招锁定。旧模式的短片段按实际长度结算，无回合标记的长片段按 30 秒切局；历史数据里的 30/60/90 秒结算仍按当时规则理解。

`tools/prepare_unity.py` 默认导出 `showcase`；使用 `--rehearsal-profile legacy` 可重新生成旧长单局编排。浏览器原有 90 秒排练继续使用 `legacy`，不随 Unity 默认展示切换。

Unity HUD 显示 KO 倒计时、HP、防守槽、最近接触与终局状态，按主镜头中的实际左右位置整组排列角色信息；普通场地与教堂的反向取景自动对应，玩家身份、伤害数组和赢家不交换。**Space** 暂停/继续、**R / Reset** 从头播放；**M** 切换音效、**N** 切换震屏、**Esc** 打开设置。浏览器旧模式继续显示回合比分并从对应快照跳转。

## 验证边界

本轮调整建立可回归的数值和空间规则，仍使用现有离线真人动捕排练。尚未接实时双人输入或自主对手，未增加受击动画；默认标准判定体也没有按每个模型的盔甲外轮廓拟合。动作实战胜率需要接入真人对局后继续调参。

回归入口：`uv run --locked pytest -q`、`uv run --locked ruff check .`、`uv run --locked ruff format --check .`、`uv run --locked python tools/check_contracts.py`、`node apps/motion-lab/tests/run-tests.js`。Unity 用 `DollFight.Humanoid.Tests` EditMode 检查，重新运行 `tools/prepare_unity.py` 后构建。

以下 2026-11-06 本机记录对应当时的三回合排练版本，用于保留历史证据；它们不代表当前 KO 单局的最终构建验收：226 项 Python 测试通过、1 项跳过；14 项 Node 测试、Ruff、协议样例和 6 项 Unity EditMode 检查通过。Unity 实际播放确认标准判定体能显示，末尾 `playing=false`，比分与 Python 快照一致。原场地及教堂 Windows 构建均通过，两份构建里的 `duel.json` 与源导出文件逐字节一致。

实际比例的 2700 帧排练保留 8 次命中、10 次格挡、4 次挥空和 6 次未提交；每回合 HP 为 89/84、80/68、100/64，最终 P1 以 3:0 获胜。这是既有独立动作编排的结果，不是玩家胜率统计。轻量验收结果在本地 `outputs/combat-review/replay.json`，EditMode 结果在 `editmode.xml`，判定体和最终比分截图在同目录。

教堂独立程序在 Direct3D 12 下启动并完成 3 秒逻辑运行，356 帧中非有限骨骼数据为 0。隐藏窗口的原生截图未成功，因此不将这次短程运行当作完整图形或性能验收；图形检查使用实际 Unity Editor 画面。
