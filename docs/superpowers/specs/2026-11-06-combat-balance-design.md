# 普通战斗规则设计

目标：在现有离线双人动捕排练上完善碰撞、普通攻击伤害及胜负判定。Python 是规则源，浏览器和 Unity 消费相同结果；不新增特殊技能或实时输入。

## 碰撞和伤害

拳和膝采用球形攻击体，踢腿采用脚踝至脚尖胶囊。受击体覆盖头、躯干、大腿和小腿，衣服、头发、装饰和个人视角修正不参与判定。两人运动同时插值，仅在有效攻击时段内检测，跟踪恢复不得连接无效历史位置；每次出招最多结算一次，重复事件 ID 不得重复攻击。

| 动作 | 伤害区间 | 基准伤害 |
| --- | --- | --- |
| 直拳 | 6–10 | 8 |
| 勾拳、普通反手拳 | 8–12 | 10 |
| 上勾拳 | 9–13 | 11 |
| 旋转反手拳 | 12–17 | 14 |
| 膝击 | 10–15 | 12 |
| 前踢 | 11–16 | 13 |
| 侧踹 | 13–19 | 16 |
| 回旋踢 | 14–20 | 17 |
| 旋踢 | 17–24 | 20 |

腿部伤害低于躯干，头部略高，命中前摇/后摇可增加 2 点，最终限制在动作区间内；伤害确定且不受识别置信度、帧率或随机数放大。旋转和重踢保留更长回收时间。识别事件表示已识别到动作，不人为补加前摇；参考指令严格使用已有标注时序。

保留已有实体前臂格挡、拨挡和防守槽机制。普通格挡无血量削减，重攻击消耗更多防守槽，破防具有完整硬直；受击会中断后续攻击。同一采样时刻双方已成立的命中同时结算，允许互击及双 KO，避免玩家编号优势。不同时间先命中的攻击应中断后到的攻击。

## 胜负及回放

每回合 100 HP，排练保持三回合、每回合 30 秒。KO 立即锁定该回合血量，双方同时归零为双 KO 平局；时间结束比较剩余 HP，同血为平局。每回合独立恢复血量、防守槽和硬直。三回合结束以胜场数判定比赛胜方，胜场相同为平局，不额外以累计血量打破平局。短单片段以片段长度作为单回合时限。

回放保留原动画时钟和跳转功能；回合提前 KO 后继续播放排练但停止该回合伤害。最终比赛结果保留在最后一帧，播放结束停止，不自动循环。重播或跳转直接读取已生成快照，不二次结算。

帧快照增加 `round_state` (`active`/`finished`)、`round_winner` (-1 平局/未决，0/1 玩家)、`round_reason`、`round_remaining`、`wins`、`match_state`、`match_winner`、`round_label`、`match_label`。比赛结果另放在 `duel.match`，每回合结果保留 `round`、`health` 并增加 `winner`、`reason` 和时间。

Unity 导出增加对应的 camelCase 字段、格挡槽、最近命中标签、结果；Unity 和浏览器均显示倒计时、比分和结算原因。Unity 可切换标准判定体可视化，使用导出的权威骨架，不按 FBX 盔甲扩大范围。

## 验证

回归覆盖动作区间、部位差异、同帧互击/双 KO、前后摇、重复事件、快速穿越、脚尖接触、小腿接触、跟踪恢复、格挡/破防、KO 后冻结、超时平局、跨回合重置、最终比分及 Unity 导出字段。执行 Python、ruff、协议、Node 和 Unity 编译/原有 EditMode 检查，重新准备实际比例的三回合回放并检查结果。
