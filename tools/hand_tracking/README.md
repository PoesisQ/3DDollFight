# 手部骨架识别

在全身骨架被追踪的同时，把 Astra 彩色画面里的双手变成 **21 个手部关节**，挂到角色手腕骨（也就是手臂骨架末端）上，逐个指节驱动。

设计说明见 [docs/hand-tracking.md](../../docs/hand-tracking.md)。

## 和一版（只有弯曲度）的区别

| | 一版 | 现在 |
|---|---|---|
| 数据 | 15 个弯曲角度 | 21 个关节的局部坐标 + 15 个弯曲角度（兼容） |
| 与身体骨架的关系 | 两路各自独立 | 手腕为锚点，手部骨架长在手臂末端 |
| 驱动方式 | 按固定轴旋转 | 每根指骨沿对应的实测段方向旋转 |
| 手指张开 / 拇指对掌 | 不支持 | 支持 |

## 1. 装一次

```bat
cd tools\hand_tracking
install.cmd       :: 建 .venv（Python 3.10）并装 MediaPipe
fetch_model.cmd   :: 下载 hand_landmarker.task（约 7.8 MB）
```

模型不随仓库分发，`.venv` 与 `models/` 都已被 Git 忽略。

## 2. 每次这样跑

Unity 打开 `Assets/AstraUnity/SingleCameraGame.unity`，按 Play，完成选角。就这样，不用再双击任何脚本。

**选角一结束，Unity 会自己启动 `run.py --start-bridge --preview`。** 面板上原来的「启动摄像头」按钮已经删掉，因为它会和 `run.py` 拉起的发送程序抢同一台 Astra；想手动接管时，先取消勾选 `AstraLivePlayer.autoStartPipeline`，再双击 `run.cmd`。

预览窗口叫 `DollFight camera + body skeleton`，彩色画面上叠了两层东西：

- 双手 21 个**绿点**，以及每只手旁的 `palm` / `back` / `edge`；
- 身体 19 个关节：**橙色骨线 + 青色关节点**，直接用传感器自己算的像素位置画在你身上。变暗的关节是「最后一次确认的位置」——见下。

骨架的 2D 位置不是这边另算的：桥在每帧报文里附上 SDK 对每个关节的投影（`screen` 字段，单位就是画面像素）。以前这里拿三维坐标按 60° 视场角反推，内参是猜的、轴向也是猜的，结果人和骨架经常左右错开——现在不猜了。`screen.ok` 为 false 的关节（未追踪、或 SDK 没给出投影）不画。

**手臂贴着身体时，那几条骨线会变暗、停住不动**，这是有意为之。深度图里手臂和躯干是同一片表面，SDK 分不开，会把肘/腕标成低置信度，位置则用它自己的模型补——补出来的手臂是往侧面伸的（T 姿那一套）。直接画出来就是「人站着，骨架手臂甩到身体外面」。所以只有高置信度的关节算「活的」，其余停在最后一次确认的位置（暗色），0.5 秒内没有新确认才消失：不闪、不飞，而且看得出来这一段是旧的。

左上角的 `fps  hands=N  body=M sure=K` 里，`body` 是这一帧落在画面内的关节数，`sure` 是其中高置信度的。两个数差得多，就是有肢体被挡住了（手臂贴身最常见）；`body` 为 0 表示身体没被追踪到；只有 10 来个数则多半是你站得太近，腿出了画面。

`run.py` 会自己拉起发送程序：彩色帧走 TCP 7005，身体骨架同时镜像到 UDP 7012 供左右手配对，手部骨架发给 Unity 的 UDP 7011。

身体骨架默认走 Orbbec SDK 内置试用，和旧面板的「启动摄像头」完全一致。有正式授权时，把授权文件放到 `H:\astra-lab-env\astra-body-license.txt`，或设置环境变量 `ASTRA_BODY_LICENSE` 指向它，脚本会自动带上 `--license`。

停下来：按 Esc 或关掉命令行窗口；也可以直接停止 Play——Unity 用 `taskkill /T` 结束整棵进程树，发送程序不会留下来占着摄像头。游戏画面上的状态面板默认隐藏，按 **F1** 可以调出来，里面有连接、校准、手部驱动和「摄像头：…」的当前状态。

> **使用注意：双臂交叉不要超过三秒。**
> 两只手掌叠在一起时 MediaPipe 会把双手一起丢掉，接收端只保持 `HandGrace = 2.5 s`，超时后 `RelaxHand` 把两只手松回绑定姿势；而交叉姿势下掌面正侧对镜头、`_settle_basis` 又只能沿用那一帧已经松过的侧，腕子就追不回来了——**只能重启 `run.cmd`**（Unity 不用重启）。
> 交叉 1–2 秒就放开，或者交叉完把手放低一下让追踪器重新咬住掌面即可。机制与修法见 [交付说明 §2026-11-11 傍晚](../../docs/hand-tracking-report.md#2026-11-11-傍晚交叉不要超过三秒先把它写成规矩)。

## 3. 参数

```bat
.venv\Scripts\python.exe run.py --help
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--start-bridge` | 关 | 由脚本拉起 `AstraUnityBridge.exe --color-port 7005 --mirror-port 7012` |
| `--color-port` | 7005 | 彩色帧 TCP 端口 |
| `--hand-port` | 7011 | 发给 Unity 的手部 UDP 端口 |
| `--body-port` | 7012 | 镜像身体骨架的 UDP 端口，用于左右手配对；0 关闭 |
| `--mirror` / `--no-mirror` | 开 | 交换 MediaPipe 左右手判定。Astra 彩色图未镜像，而 MediaPipe 按自拍镜像图输出，所以要交换 |
| `--license` | 自动查找 | 身体跟踪授权文件。不填时依次查环境变量 `ASTRA_BODY_LICENSE`、`%ASTRA_LAB_ENV%\astra-body-license.txt`，与 Unity 面板的逻辑一致 |
| `--preview` | 关 | 弹出预览窗口：手部绿点 + 身体骨架，Esc 退出 |
| `--min-confidence` | 0.5 | 低于该置信度的手直接丢弃 |

有身体骨架时，左右手由**两只手腕的左右顺序**决定，`--mirror` 不再参与；只有拿不到身体数据时才回退到 MediaPipe 标签（此时 `--no-mirror` 可关闭交换）。

## 4. 发给 Unity 的报文

`dollfight-hands-3`，UDP 7011，UTF-8 JSON：

```json
{"version":3,"session":"...","sequence":12,"timestampMs":3456,
 "hands":[{"side":"Left","confidence":0.93,"gesture":"open","scaleMm":82.4,
           "joints":[63 个数],"curls":[15 个数],"basis":[9 个数]}]}
```

- `joints`：21 个关节 × (x, y, z)，以**手腕为原点**、按掌心长度归一化。坐标轴为
  `x = 食指根 → 小指根`、`y = 手腕 → 中指根`、`z = x × y`，左右手用同一套构造。
- `scaleMm`：实测掌心长度（手腕到中指根），用于诊断，不参与驱动。
- `curls`：一版的 15 个弯曲度，保留给旧接收端和握拳判定。
- `basis`：同样的三个坐标轴，但表达在 Astra 相机系下（X 右、Y 上、Z 朝向场景），每轴 3 个数。
  21 点全在手的自身坐标系里，说不清手整体朝哪；`basis` 补的就是这个整体姿态，接收端用它
  把角色的手腕三维朝向对齐到真人，翻掌、压腕都能跟上。
- **关节来源**：由 `hand3d.py` 从二维关键点重建，**不用 MediaPipe 的 `world_landmarks`**。
  那一层三维回归在手背离镜头时会塌（掌长 100→36 mm、掌宽 65→7 mm、帧间掌法线最大转 120°），
  而且分不出手指弯没弯：同一段录屏按人眼分组，它给张开手 144.8°、握拳 134.6°，方向是反的。
  重建方法：掌心当刚性平面定姿态，手指当一自由度链，用「弦长比 + 二维折返度」反解弯曲量，
  再按真人屈曲曲线展开三个关节。拇指的起始方向从关键点直接测，因为「竖大拇指」是拇指摆出
  掌面而不是弯曲。
- **轴向**：重建在图像系里建轴（X 右、Y 下、Z 进场景），发报文前做 `(x, -y, -z)` 转到接收端
  用的世界系（Y 上）。这步删不得：漏掉它腕子恒定差 180°，角色只露手背。两端放进同一个
  数值模型量过——不换算 180°，换算后 0°，左右手都一样。21 个局部坐标不用动，点和轴一起
  转动时「点 · 轴」不变。
- **`PALM_SIDE`**：`z = x × y` 在左右手指的不是同一侧（右手指掌心、左手指手背），它是手指
  该往哪边弯的唯一依据，符号反了会让所有手指朝手背折、并把首帧掌面分支选反。
- **`z` 的深度符号由 2D 关键点决定，不靠时间连续性**：`x`、`y` 都躺在像平面里，它们的叉积的
  z 分量就是二者的 2D 行列式，逐帧精确、没有二义性（`palm_depth_sign`）。翻掌是一次
  180° 跳变，连续性分不出「真翻掌」和「world landmarks 把法线扔到手背那侧」，所以这一位
  必须由画面说了算；连续性只用来平滑剩下的抖动。曾经用「跳变 >35° 就沿用上一帧」来挡噪声，
  结果翻掌那一帧被判为噪声、又因为被拒的帧不更新参考而永远拒绝，那只手会一直保持翻手前的
  朝向直到整只手丢失（实测一段 42 秒录屏，27% 的帧至少一只手是反的）。
- 接收端校验：`version` 为 1/2/3；`hands` ≤ 2；v2 起必须 63 个有限坐标、`scaleMm` 在 12–250 mm；v3 还必须 9 个 `|值| ≤ 1` 的 basis 分量。

报文仍然独立于 19 点身体报文，符合 `docs/contracts.md:47`「不能偷偷塞进固定 19 点字典」。

## 5. 排查

| 现象 | 处理 |
|---|---|
| `连接不上彩色流` | 发送程序没用 `--color-port` 启动，或被别的进程占着摄像头 |
| 帧率只有 20 多 fps | 看命令行每 60 帧那行：`N 帧 N fps` 是**处理**帧率，`相机 X fps` 是本机实际从桥上收帧的速率。两个数接近，瓶颈在相机或桥（Astra 出 30 fps，身体追踪会拖低）；处理明显低于相机，才是本机算不过来——先关掉预览对比，预览的 `imshow` 在 Windows 上是这几段里最贵的一段 |
| 拖动预览窗口时整个手部卡住 | 已修：预览在独立线程（`preview.py`），窗口被拖动时只丢预览帧，追踪和 UDP 照常跑。同时 `read_latest()` 会丢掉积压的旧帧，避免延迟越拖越大。若仍卡，是窗口本身的重绘开销，不是追踪停了 |
| 骨架手臂甩到身体外面、左右乱跳 | 多半是手臂贴着躯干：深度图分不开两层，SDK 降置信度并用模型补位。现在低置信度的关节会变暗并停住（见第 3 节），不再乱飞。想让它更准：退到 2–3 m、把袖子换成和背景反差大的颜色、手臂和身体留一点缝 |
| `sure` 一直远小于 `body` | 同上。整段肢体都被判低置信度时，先把人放远、让全身进画面；还不行就是那一段确实被挡住了（桌子、椅子、抱枕） |
| `找不到手部模型` | 先跑 `fetch_model.cmd` |
| 面板一直「未收到手部数据」 | 检查 UDP 7011 是否被占用；看命令行有没有在出帧 |
| 面板「连接：UDP 7001 未绑定」 | 端口被上一次 Play 遗留的 socket 占着。先点面板「重连 UDP」；仍失败就彻底退出 Unity（不是退出 Play）再重开，用 `Get-NetUDPEndpoint -LocalPort 7001` 确认已释放 |
| 手很小、识别不到 | 靠近到 1.5 m 内；开灯（Astra 彩色实测偏暗） |
| 左右手反了 | 确认 7012 没被占用、发送程序带 `--mirror-port`；这会启用左右手配对。若仍相反，改用 `--no-mirror` |
| 手指朝反方向弯 | 把 `--preview` 打开，确认 21 点贴在手指上；坐标轴构造见第 4 节 |
| 握拳时手指不弯 / 张开时手指自己弯 | 先看 `--preview` 里 21 点是不是跟着手指走。弯曲量现在是**拟合**出来的：按候选弯曲量把手指重建、投影，再和观测到的三段指骨比（差一个整体缩放，最小二乘解出）。若仍不对，多半是掌面法线锁到了镜像分支——把手掌正对镜头停一下就复位。见 `_fit_curl` 与 `CURL_FLOOR` / `CURL_CEILING` |
| **角色站着但姿势和人对不上 / 鞋底翻着、脚尖翘** | 游戏画面顶部有没有一行黄色 `Astra：未绑定`；`Library/AstraLiveStatus.txt` 的 `calibrated=` 是 False 吗 | 这是**身体没绑定**，角色还在放回放 clip。`ApplyBodyPose` 只在 `Calibrated` 时执行，而 `ApplyHands` 不受它约束——所以手指会动，身体不动，很容易误判成「已绑定但姿态算错了」。回放 clip 自己的鞋底法线就偏 17–29°（`player-1-motion.json` 逐帧量过），量出来正好对上屏幕上的翘脚。现在：站到镜头前 6 秒仍没有 T 姿就按**当前站姿**自动绑定（`status` 变 `Live P1 (站姿绑定)`），顶部会显示绑定状态；平举一次双臂则升级成按模型 rest 精确绑定 |
| **角色脚尖翘起 / 鞋底像从脚掌中间折了一下** | 2026-11-24 定位：`PlantFeet` 把脚掌摆平之后，**脚趾骨（`LeftToes` / `RightToes`）没有跟着**——它们不在这套骨骼驱动表里，仍由回放 clip 每帧写入（`DollFightDemo.Update` → `HumanoidReplay.Apply`），而 clip 的脚趾朝向是照着 clip 自己的脚算出来的。鞋底是一整块刚性网格：mizore 的接地顶点里 133/509 主要由脚趾骨控制、478 个带脚趾权重，脚趾歪多少鞋头就翘多少。现在 `PlantFeet` 摆平脚掌后把脚趾按建模时的相对角度挂回去（`toeBindings`，实测模型 rest 是 0.00°，所以未绑定时用恒等也正确）。**摆平只做一次旋转，用的是建模鞋底方向**（`TrySoleUp`），不再「量一次残差再修一次」——那条路 2026-11-25 12:01 已经走死了，见下面「站着时脚掌内翻」那行。`soleLeft` 仍然会报一个残余，但它是**独立读数**，不参与任何旋转：鞋底采样点只要 65% 权重落在脚掌上就算数，剩下最多三成跟着小腿走、不随脚掌转，所以脚骨摆平之后画面上仍可能留一点 roll——这是权重决定的，继续转脚掌只会把脚转坏。状态文件：`toeFix=` 脚趾被拉回的角度、`soleTilt=` **摆平之前**鞋底偏多少（clip 自己的 roll，实测 17–29°）、`soleLeft=` **摆平之后**用主轴拟合独立量到的残余（近 0 说明建模鞋底和网格一致；和 `soleTilt` 一样大说明**建模鞋底本身错了**）、`soleYaw=` 摆平会转掉、随后被恢复的脚趾方向（度）、`soleLift=` 髋部抬/压的厘米数、`soleAir=` 这一帧没摆平（离地）的脚 |
| **脚内翻 / 内八字，鞋像踩在侧面** | 2026-11-25 定位：`soleTilt` 降到接近 0（鞋底确实平了）但脚趾朝身体内侧 | `Quaternion.FromToRotation(worldUp, up)` 是**最短旋转**：所有让鞋底法线朝上的旋转都同样「平」，最短那个会把脚趾一起带走。鞋底那 22° 的偏差有很大一部分是**横跨脚掌**的，摆平它等于把脚绕垂直轴转了一个角度。现在每次摆平都用 `AimSole`：先记下脚尖的水平方向（`toe.position - foot.position`，mizore 里前方 10.8 cm），转平后绕垂直轴把方向转回去——绕 Y 的旋转不改变任何向量的高度，所以鞋底仍是平的。`soleYaw` 就是被恢复的角度（修复前这个角度会留在脚上，就是内八字的来源）；如果它很大而脚看起来仍朝内，那是 clip 自己的站姿，不是摆平造成的。两条护栏：鞋底离地平面超过 `MaxSoleTilt`（65°）**不摆**（那不是站在地上，是从那儿转下来会把脚翻过侧面）；`ToeDirection` 在脚尖接近竖直时返回 false（水平投影只剩噪声，归一化它等于随机转脚） |
| **还没绑上时脚尖就翘着** | `calibrated=False` 时脚尖翘 | 这是回放 clip 自己的脚：量化过，`player-1-motion.json` 的鞋底法线偏 17–29°，鞋跟落地、鞋头朝上。以前 `PlantFeet` 只在 `ApplyBodyPose` 里调用，也就是**只有绑上才摆平脚**，于是没绑时整段都是 clip 的翘脚。现在 `LateUpdate` 在没身体时也调 `PlantFeet`：只摆平**贴地**的那只脚（离地超过 3 cm 的是在抬腿，不碰，否则走路会变成滑步）。这条不依赖绑定，`toeBindings` 在建模型时就是恒等（clip 里 `inv(rot13)*rot14` 量到 0.0°），所以没绑也不会错 |
| **踢腿时鞋整个反过来 / 抬腿时鞋子留在原地不跟着腿** | 2026-11-25 定位，两个现象同一个根。①`FitSoleUp` 把鞋底平面写在**脚骨自己的坐标系**里（`y = ax + bz + c`），再加一条 `up.y >= 0.35` 的「这真的是鞋底吗」校验。但 humanoid 的脚骨通常**指向脚尖**而不是从鞋底朝上：从 `TripoB9E9.prefab` 直接解出的静止姿态里，世界「上」在脚骨局部是 `(-0.50, -0.68, 0.54)`，`up.y = -0.68`，于是**每一帧都判定没有鞋底**，`soleUpKnown=false`。②于是 `PlantFeet` 走 `facing * bindRotations[foot]` 分支——把脚强行摆回**绑定姿态的朝向**，与腿当前指向无关；腿一抬，鞋就留在世界坐标里那副平放的样子，脚踝看起来像断了，紧接着那次「测量拟合」再把它转过去，就成了翻鞋。修法：`FitSoleUp` 改为**主轴拟合**（采样点协方差的 Jacobi 分解，取方差最小的方向 = 鞋底法向），不再假设鞋底垂直于脚骨任何一根轴；先沿法向投影取最低 2 cm 的**接地面**再拟合一次（这双鞋足弓比接地点高 15–23 mm，全部 36 个点一起拟合偏 3.0°，接地面 19 个点只偏 0.9°），符号由「导入时模型站在地上」定，最后 `foot.InverseTransformDirection` 换回脚骨局部。实测把采样姿态整体转 22°/70°，算出的局部法向完全一致。`PlantFeet` 改由 `FollowAnkle`（`bones[foot] = bones[shin] * ankleBindings[side]`）让脚跟着小腿走，抬在空中的脚**完全不摆平**。`soleAir=L/R` 标出这一帧哪只脚在空里 |
| **站着时脚掌内翻（靠外缘站），一踢出去反而正常** | 站立时 `soleTilt` 读到十几到二十几度，`soleLeft` 同样大 | 踢出去的脚在 `soleAir` 里**完全不摆平**，走 clip 原样，所以看着正常；站着的脚要摆平，而**摆平用的平面是错的**。`TrySoleNormal` 拿**全部**采样点做最小二乘，但采样器存的是每个 25 mm 格子的最低顶点：脚下的格子取到鞋底，脚踝周围和脚背上方的格子取到的是**鞋帮**——穿过两者的平面既不贴鞋底也不贴鞋帮。<br>2026-11-25 11:30 曾试图只取「沿参考方向最低 20 mm」的接触面来救，结果**更糟**：那条参考方向是「建模鞋底方向 × 当前姿态」，而当前姿态正是要纠正的东西——带子按鞋已经歪到的角度切，`soleBand=18/18`（整只鞋都被圈进去），拟合出穿过鞋帮的平面，刚好摆平的鞋被读成还差 **28.7°**，下一趟就去追这个假角度，鞋被继续滚到外侧棱上。**用被纠正的姿态去定义测量，是反馈环**。<br>现在：站着的脚只用**建模鞋底方向**（`TrySoleUp`，脚骨局部的一个常量）一次摆到水平，不再重测、不再迭代；`TrySoleNormal` 只作读数，改成**主轴拟合**（协方差最小特征方向），姿态无关，且**不参与任何旋转**。`soleTilt`=摆平前的偏角（clip 的 roll），`soleLeft`=摆平后独立量到的残余：两者都大说明**建模鞋底本身错了**，而不是摆平错了 |
| **手伸直时手掌绕小臂打圈** | `holdL` / `holdR` 持续增长；`rollL` / `rollR` 在 0–180 之间来回跳 | 2026-11-25 定位：**不是回放动画**——量化过 `player-1-motion.json`，手腕（bone 7/10）相对前臂恒为 **0.0°**，clip 根本不转手腕。是 tracker 送来的手掌坐标系在翻：`hand3d.palm_depth_sign` 从 2D landmarks 的 2×2 行列式读「哪一面朝镜头」，手掌**侧对摄像头**时（正是手臂伸直的姿势）行列式接近 0，一两个像素的噪声就能让符号翻转；`_settle_basis` 对大于 `BASIS_SNAP`（10°）的跳变是**直接接受**的，于是目标每帧翻 180°，Unity 再按 `wristTurnRate`（720°/s）追过去——两秒一圈，就是打圈。现在 `HumanoidReplay.ApplyHandSkeleton` 对「跳变」先不追：目标与当前差超过 `wristJumpDegrees`（100°）时，要求同一个目标连续保持 `wristJumpConfirm`（0.12 s）才跟随。真翻掌每帧都指向新的一侧，0.1 秒后就跟上；噪声翻转是交替的，永远攒不够时间，手停在原处而不是转圈。`holdL` / `holdR` 是收到「跳变目标」的帧数——这些帧里手先不动、等确认：手没动却在涨 = 上游在翻符号；一直是 0 = 姿势本身平滑，这条没触发 |
| **Unity 一直「未绑定」，预览窗却有 19 个关节** | 状态文件 `body.sessions=` 和 `withBody=`；`sessions=2` 说明端口上有两个发送方 | 两路发送方在同一个 UDP 7001 上：早先那次留下的 `AstraUnityBridge.exe` 还活着，它没有 `--color-port`（探不到端口、老代码不会清它），却仍占着摄像头；SDK 的 body 流只给一个 reader，于是**会话自己那路收到空 `bodies`，僵尸那路才有人**。旧规则是「谁先说话就一直用谁」，于是一整场都跟着空流，面板写「等待被跟踪的人」，旁边的预览窗却在画 19 个确信关节。现在接收端**优先跟随有 body 的那一路**（工作流只让位给另一路也有 body 的情况），并且 `StartPipeline` 会无条件清掉本工程构建的所有 bridge 进程。如果 `body.sessions=1`、`withBody` 在涨、`legNote` 有值却仍然 `calibrated=False`，看下一行 `calibNote=`：它是 `Calibrate` 拒绝的第一条检查（`hip status 0` / `segment i` / `shoulders`）。这些分支过去是静默 `return false`，页面只显示笼统的「等待」，分不清「没人在画面里」和「有一个关节没跟上」 |
| **角色一直在放回放动画：会自己走位、并腿，不跟你的动作** | 状态文件 `calibrated=False`，画面顶部黄字写着「未绑定（现在是回放动画）」 | 身体数据是稀疏的，会断帧。旧代码在**未校准**时只要有一帧没有 body 就把 `bodySeenSince` 清成 −1，于是 `StanceBindDelay`（6 秒）的站姿计时**永远攒不满**，`Calibrate` 一次都没被调用（`calibNote=-` 就是证据）。现在用 `lastBodyFrame` 在 `BodyGrace`（2 秒）内桥接空帧，计时可以继续累积，自动站姿绑定才可能触发。角色腿上那些交叉步、并腿、走位是回放 clip 自己的，不是你的腿 |
| **预览窗里「左右小腿靠到一起」** | 骨架整体大小在变，手臂一抬就缩一圈 | `DrawPreview` 原来按**当前帧所有关节的包围盒**算缩放：手一平举，包围盒变宽，整个人缩小，两条小腿在屏幕上只剩几个像素的间距，看起来像腿并拢了。现在改成固定比例（1.9 m 宽 / 2.2 m 高）并绕髋部居中，姿势变化不再改变缩放 |
