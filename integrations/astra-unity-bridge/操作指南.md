# Astra 摄像头接入与操作指南

本文介绍当前分支的 Unity 游戏工程如何接入 Astra 骨架。现在可以用一台摄像头控制游戏中的 P1；另有一个双摄骨架展示场景。**双摄展示尚未接入双人角色控制或战斗判定。**

## 1. 准备环境

- Windows、Git 和 Git LFS。克隆项目后在仓库根目录执行 `git lfs pull`，确保角色等 LFS 资源已下载；游戏所需的动作数据也需按[Unity 工程说明](../../unity/README.md)准备。地下竞技场可优先用于测试，其他场地资源可能需要单独恢复。
- Unity Hub、Unity Editor **6000.3.27f1** 和 Unity 许可。将仓库中的 `unity` 文件夹添加到 Hub；首次打开需等待包导入与脚本编译。
- Astra 摄像头及其可用的驱动、Astra SDK 2.1.3、CMake 和 Visual Studio 2019 C++ x64 构建环境。SDK、授权文件和编译产物不包含在仓库中，需由使用者自行准备。

Hub 点击项目没有反应时，检查“安装 / Installs”中此版本的编辑器路径；必要时选择“定位 / Locate”，指定实际安装的 `Unity.exe`，再用 Hub 打开项目。项目目录是仓库下的 `unity`，不是仓库根目录或本集成目录。

## 2. 构建骨架发送程序

发送程序从 Astra 获取骨架，通过本机 UDP 发给 Unity。需准备一个实验环境目录，至少包含下列文件和 SDK 运行所需的其余文件：

```text
<lab-env>/
  cmake/tools/bin/cmake.exe
  astra/sdk/include/astra/capi/astra.h
  astra/sdk/lib/astra.lib
  astra/sdk/lib/astra_core.lib
  astra/sdk/bin/...
```

打开 PowerShell，把下面的路径换成**自己电脑上**的实际位置：

```powershell
cd <仓库路径>\integrations\astra-unity-bridge
$env:ASTRA_LAB_ENV = '<lab-env 的完整路径>'
.\Build-Bridge.cmd
```

如果仓库路径中有空格，请给 `cd` 后的路径加引号。构建成功后生成 `build/bin/Release/AstraUnityBridge.exe`。模拟模式也使用这个程序，首次使用前同样需要构建。

需要指定人体跟踪授权文件时，在**启动 Unity 的同一个环境**中设置 `ASTRA_BODY_LICENSE` 为授权文件完整路径。若未设置而 `ASTRA_LAB_ENV` 下存在 `astra-body-license.txt`，程序会尝试使用该文件；否则由 SDK 按其试用条件运行。不要提交授权文件、SDK 或 `build/` 到 Git。

## 3. 单摄控制 P1

1. 用 Unity Hub 打开 `unity` 工程，在 Project 面板打开 `Assets/AstraUnity/SingleCameraGame.unity`。也可通过菜单 **DollFight → Astra → Open Single Camera Game** 打开。
2. 关闭其他可能占用 Astra 的 Viewer 或发送程序，连接一台 Astra。点击顶部 **Play**，选好双方人物和场地，建议先选择地下竞技场。
3. 在 Game 画面左上角的状态面板点击**启动摄像头**。确认出现“已收到摄像头数据”和“已识别 1 人”。
4. 面向摄像头站立、尽量让身体入镜，双臂向两侧平举。程序每隔 5 秒尝试自动校准；成功后显示“已校准，控制 P1”。校准失败的提示和骨架小窗可用来判断缺失关节或姿势问题。
5. 移动手臂和身体，观察游戏中的 P1。按 **V** 可切换游戏的玩家视角窗口。再次保持平举姿势时，后续自动校准可能更新基准；数据中断、更换跟踪对象或重新选角后需重新校准。
6. 结束时先点**停止数据源**，再停止 Unity 的 Play。面板只能关闭由它启动的发送程序；若使用外部命令窗口启动，需要手动关闭该窗口。不要同时启动两个发送程序。

如果只想排查 Unity 接收和人物控制链路，可在面板点击**启动模拟**，等待自动校准；模拟数据不代表真实摄像头已通过测试。

### 状态和骨架小窗

小窗是关节位置的正面投影，**不是摄像头视频**。青色表示正常跟踪，黄色表示低置信度，未追踪关节不显示；左右脚末端两个关节被单摄控制和小窗忽略，因此最多显示 17 个点。SDK 仍可能采集和发送这两个点。

- **未收到数据**：确认已构建发送程序、启动了正确的数据源，并检查是否有端口占用或发送程序报错。
- **未识别到人**：检查设备连接、授权、摄像头视野和人体跟踪；先关闭其他 Viewer。
- **校准失败 / 未追踪某关节**：按提示调整站位，让头、躯干、双臂及膝盖尽量可见，双臂平举等待下一次尝试。
- **骨架出现但人物不动**：确认已完成选角和场地选择、已显示校准成功；先使用模拟模式区分游戏链路与设备问题。
- **第一人称窗口没出现**：在游戏中按 **V**。窗口跟随模型头部位置和倾斜，头部左右转向尚未可靠接入。

## 4. 两台摄像头的骨架演示

打开 `Assets/AstraUnity/DualCameraDemo.unity`，点击 Play。测试模拟数据时运行本目录的 `Run-Dual-Simulation.cmd`；连接两台 Astra 后，可关闭模拟程序和其他 Viewer，再运行 `Run-Dual-Live.cmd`。

两台设备分别对应 `device/sensor0` 和 `device/sensor1`，接收端默认使用本机 UDP 7001 和 7002；每路只显示一个人，两具骨架在画面左右分开。重新插拔后设备编号可能改变。该场景不进行共同空间标定，也不能保证两路没有识别到同一人。双路模拟曾通过验证，两台真实 Astra 同时工作尚待实测。

## 5. 当前能力和限制

- 单摄模式已在一台真实 Astra 上观察到 P1 跟随；不同设备、模型、方向和现场环境仍需分别验证。角色初次从游戏设定的位置开始，并朝向对手；实时战斗、伤害及胜负识别尚未接通，原有回放战斗在此模式暂停。
- 大腿依赖髋部和膝盖；因为暂不使用摄像头脚点，模型小腿保持垂直向下，不代表真实屈膝，脚也没有实时贴地校正。
- 躯干扭转、手指、脚尖和头部左右转动尚未可靠跟踪。摄像头的左右、前后方向和身体比例仍可能需要按实际设备调整。
- 原独立 `UnityProject` 已迁入游戏的 `unity/Assets/AstraUnity/`，使用游戏工程即可。
